# v5 NTASAD companion dataset

V5 inherits `plan-v4.json` and its exact generated camera configurations:
234 eight-frame clips / 1872 frames, including the explicit anchor cameras and
0.6/1.8/3.6 motion profiles. The source dataset is `../dataset/denoiser-v4`.
It can finish on the other machine; planning does not require its pixels.

The new tool copies each verified completed source `manifest.json` and
`frame.exr` byte-for-byte. The original EXR retains the 4-SPP radiance, 1024-SPP
reference and all guides. That noisy radiance is reused as the **4-SPP layer**.
Only independent 1/2/8/16/32-SPP means are rendered, adding **59 paths/pixel**.
No reference or guide pass is repeated for these companion layers.

## Plan now

From the denoiser root, with the project installed:

```bash
python3 tools/generate_adaptive_dataset.py \
  --source ../dataset/denoiser-v4 --output ../dataset/denoiser-v5 --stage plan
```

This writes configs, inherited partitions, a provenance lock, storage estimates
and training-plan sidecars. It does not render, copy source frames or change v4.
It works before the source directory exists. Keep this plan separate from the
ordinary v4 capture launcher; `generate_dataset.py` still defaults to v4.

## Build the layer capture executable

From the renderer root on an RTX 3090 machine:

```bash
cmake -S . -B build/ntasad-v5 -DCMAKE_CUDA_ARCHITECTURES=86 \
  -DCMAKE_BUILD_TYPE=Release -DPATHTRACER_BUILD_DATASET_CAPTURE=ON
cmake --build build/ntasad-v5 --target dataset_capture frame_export_tests --parallel 2
```

Use this separate build instead of replacing a binary that an active v4 capture
has locked. V5 records both the source binary's digest and its own capture
binary's digest; the digests may differ, but exported integrator settings,
integrator version, scene fingerprints, cameras and original RNG conventions
must agree. Keep the new binary unchanged once companion capture begins.

## Capture a pilot after v4 frames are available

From the denoiser root, choose one training and one validation clip:

```bash
CUDA_VISIBLE_DEVICES=0 python3 tools/generate_adaptive_dataset.py \
  --source ../dataset/denoiser-v4 --output ../dataset/denoiser-v5 \
  --stage capture \
  --renderer ../new/build/ntasad-v5/dataset_capture --renderer-root ../new \
  --groups bmw_view_00_linear_slow bathroom_view_00_linear_slow
```

Replace `../new` if the renderer checkout has a different name. The source's
scene/config/asset paths must resolve on the capture machine, and their bytes
must still match its capture lock. Run beside the original v4 assets or retain
the original path layout when moving the source; silent asset-path remapping
is not implemented. The production companion plan remains full-resolution and
does not change reference counts for a cheaper pilot.

`--frame-range 0 2` limits each selected clip to its first two frames; omit it
on the next run to finish the clips. Missing source frames are reported as
`pending_source_frames` and left untouched. Rerun after v4 publishes them.
There is no background waiting loop. Corrupt completed frames produce an error.

Omit `--groups` to capture train/validation groups. Test capture requires an
explicit test group or `--partitions test`; model selection must continue to
exclude test data. The source lock, partition manifest, selected scene assets,
original frame cameras/settings and checksums are checked before use.

One advisory output lock prevents two CLI writers from using the same v5
directory. Completed records are checksum-verified and skipped. Copied source
frames and completed layer EXRs are also reused after interruption, even if the
wrapper did not yet publish their completion records. Abandoned `.partial`
directories are retained under `recovery.partial/` before retrying. Only missing
contiguous frame ranges are sent to the renderer. Intra-frame sample checkpoint
resume and multi-GPU job scheduling are not implemented.

## RNG allocation

All offsets below are relative to the **original** source frame's `sample_start`:

| Data | Half-open sample interval |
| --- | --- |
| Reused 4-SPP input | [0, 4) |
| Copied 1024-SPP reference | [4, 1028) |
| Reserved 4096-SPP report reference | [4, 4100) |
| New 1-SPP layer | [4100, 4101) |
| New 2-SPP layer | [4101, 4103) |
| New 8-SPP layer | [4103, 4111) |
| New 16-SPP layer | [4111, 4127) |
| New 32-SPP layer | [4127, 4159) |

The training reference is a prefix of the reserved report reference, as in v4.
Every new layer is disjoint from both references, the reused input, and all
other layers. All intervals fit inside v4's 8192-sample frame stride. Per-pixel
RNG keys retain the original global pixel and absolute sample indices.
The six binary layers represent counts **0–63**; no 64-SPP claim is made.

## Files and reader

```text
denoiser-v5/
  v5_lock.json                 inherited plan/configs and source location
  capture_binding.json         source-lock and renderer digests, bound at capture
  dataset.json                 v5 groups, scene partitions and sample layout
  source_configs/GROUP.json    unchanged original capture configs
  capture_configs/GROUP.json   original configs plus layer intervals
  base/GROUP/frame_NNNNNN/     exact source manifest.json + frame.exr copies
  layers/GROUP/frame_NNNNNN/   layer-only manifest.json + layers.exr
  frames/GROUP/frame_NNNNNN/   completion manifest pinning both manifests
  split.json                  inherited split targeting base/ for uniform training
  train-uniform.json           runnable uniform-denoiser pretraining configuration
  train-joint.json             runnable two-network adaptive training configuration
  train-joint-plan.json        historical experiment description; not a trainer config
```

The layer EXR has 15 full-resolution FLOAT channels: `spp_1.R/G/B`,
`spp_2.R/G/B`, `spp_8.R/G/B`, `spp_16.R/G/B`, and `spp_32.R/G/B`.
Values are finite, nonnegative linear RGB **means**, not accumulated sums,
nested prefix averages or display-transformed values. Its manifest schema is
`cuda-wavefront-sample-layers`, version 1. It records dimensions, conventions,
current/previous cameras, frame/sequence identity, scene/render fingerprints,
common render settings, each absolute sample interval and the EXR checksum.
It makes no claim to have rendered a reference. Completion records are published
by directory rename after both source and layers pass verification.

```python
from wavefront_denoiser.adaptive_data import V5SequenceDataset, load_v5_frame

frame = load_v5_frame("../dataset/denoiser-v5", "bmw_view_00_linear_slow", 0)
# frame.layers: 6,H,W,3 NumPy means ordered 1/2/4/8/16/32 SPP
# frame.base.buffers: original noisy/reference RGB and guides

dataset = V5SequenceDataset("../dataset/denoiser-v5", partition="train", length=5)
window = dataset[0]
# window['layers']: 5,6,3,H,W torch tensor
# window['buffers']: original TCHW buffers, with initial history invalidated
```

Windows stay inside complete clips. Discovery reads only selected-partition
metadata; actual image bytes are verified lazily on access. The first frame in
each window has invalid recurrent history. The original source path is not
needed to read a fully copied v5 dataset. The joint trainer uses a crop-aware
reader instead of retaining full-resolution five-frame windows in memory.

The uniform trainer can use `train-uniform.json` after its train/validation
frames are complete. `train-joint.json` runs the five-frame, equal spatial/temporal
L1 experiment using explicit bounded allocation and resumable two-network
checkpoints. Rerun the plan stage to add this file to an older v5 plan; existing
edited configurations and `train-joint-plan.json` are preserved. See the
[joint training instructions](../docs/joint-training.md) for pilot selections,
resume, method variants and validation. The [sparse reconstruction and gradient
estimator](../docs/adaptive-reconstruction.md) remain separately documented.

## Space and validation

The five new RGB layers require about 118.7 MiB/frame or **216.9 GiB** over
1872 frames before compression. Exact source EXR copies additionally retain
22 channels, approximately **318.1 GiB**. Full v5 raw payload is therefore about
**535.0 GiB**, excluding the separate original v4 dataset and optional reports.
EXR compression changes actual disk usage; measure the pilot first.

Validation commands from the denoiser root:

```bash
python3 -m pytest -q tests/test_adaptive_dataset.py
WAVEFRONT_CAPTURE_EXECUTABLE=../new/build/ntasad-v5/dataset_capture \
WAVEFRONT_RENDERER_ROOT=../new \
  python3 -m pytest -q tests/test_adaptive_capture_gpu.py
```

GPU tests create small real captures from built-in scenes, check layer values
against independent direct renders, compare tiled/full/persistent execution,
and exercise complete eight-frame source-copy/layer-capture/resume/read/replay
pipelines. These are technical fixtures, not production camera qualification
or learned-quality results. The production v4 inputs are not on this machine
yet, so production v5 reuse/pilot validation remains pending their arrival.
